# Default to Gemini TTS, keep Qwen3-TTS 1.7B as the local engine

The Markdown narration tool now defaults to Gemini 3.8 Flash-Lite TTS through OpenRouter (`--engine gemini`), and the local Qwen3-TTS backend from ADR 0001 moves to `--engine qwen` with `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice` as its default model instead of the 0.6B. This supersedes ADR 0001's choice of default engine and default model; its chunking, explicit setup, device and `--keep-temp` decisions still hold. The pt-BR benchmark in `benchmarks/tts/` (20 sentences, Whisper large-v3 WER and a blind listening test) drove the change: Gemini scored 4.95/5 in listening against 3.25–3.40 for the best local models (Qwen3-TTS 1.7B and Fish S2 Pro), was the only engine that read numbers and abbreviations correctly, and costs about US$ 0.60 per hour of audio, using OpenRouter credits the user already has. The cost of that choice is that narration needs network access and a paid key, the document text leaves the machine, and OpenRouter's speech endpoint takes no style instruction, so `--instruct` works only with the local engine. Qwen3-TTS stays as the offline engine because it was the best local option on an 8 GB GPU: intelligibility on par with Fish S2 Pro at 5.5 GB instead of 7.6 GB, and Apache-2.0 instead of a non-commercial license. The 1.7B replaces the 0.6B because the 0.6B misread acronyms in testing and the 1.7B still fits the GPU. Voxtral 4B (int4) was rejected for unstable Portuguese output, and voice cloning (Qwen3 Base, Fish) is left out until someone needs a custom voice.
